# Core v2 — Windows x64 release, 23 September 2026

Portable executable: `dist/Core-v2-windows-x64/core-v2.exe`. Extract the ZIP before running. It requires 64-bit Windows and the Microsoft Visual C++ v14 x64 runtime, and does not need administrator access. Existing settings and command history load unchanged. This is an unsigned alpha build.

## Included changes

**Recently used apps when nothing is typed.** Opening Core shows a grid like Start's pinned apps: a large icon over each name, with longer names wrapping to two lines. It shows up to 18 apps, six across and three rows.
- **Order:** apps opened from Core come first, most recent first. The rest of the grid is filled from Windows' own usage record (UserAssist, the data behind Start's "Most used"), so it is full from the first run.
- **Matching:** Windows' records are matched to Core's apps, including Store apps, desktop apps listed by app ID, Start menu shortcuts and taskbar pins. Anything Core doesn't list, such as a program run from a folder, is left out.
- **Privacy:** the record is only read, locally, each time Core opens. Apps opened from Core are saved in `recent-applications.txt`, next to your settings, up to 50.
- **Keys and mouse:** arrow keys move between tiles and rows, and Enter or a click opens the app. Hovering highlights a tile. Typing searches as before.
- **Small or heavily scaled screens:** rows that don't fit are left out rather than cut off.

**`cd` carries over between commands.** Each command still runs in a new shell, but the shell reports the folder it finished in, and the next command starts there. So `cd Pictures` followed by `ls` lists Pictures.
- This works in every shell, including `cd src && ls`, `pushd` and `Set-Location`.
- The line above each output shows the folder the command ran in (`~\Pictures> ls`), and the footer shows the current folder.
- Ctrl+Enter and Ctrl+Shift+Enter open their terminal there too.
- The folder resets to your profile folder when Core restarts.
- The footer no longer says "Tab selects the output", to make room for the folder. Tab still works.

**Reliability.**
- Enter now checks that the results match the text in the box, and searches again first if they don't. Previously a lost edit notification could make Enter act on results for older text.
- Ctrl and Shift only count when Core is in the foreground, so a key held in another app can no longer turn Enter into "open in terminal".

## Validation

- **Rust:** 82 engine tests and 74 launcher tests pass. Three ignored tests exist for the registry, live favicon and live ECB downloads; they were not rerun for this build. `cargo clippy --workspace --all-targets -D warnings` is clean. New tests cover:
  - recent-app ordering, fallback and the 18-app limit
  - reading UserAssist: name decoding, record layout, known folders and this account's live records
  - matching Windows' names to Core's apps, including taskbar pins
  - merging Core's launches with Windows' record
  - grid arrow-key movement
  - directory reporting, live in cmd and PowerShell, including exit codes after a failed `cd`
  - reported-path handling, and the terminal and administrator arguments
- **Release scripts:** all eight background scripts pass against the packaged executable. New checks:
  - the controls check tests grid arrow keys, and the grid at 4× scaling keeps the footer and buttons on screen
  - the commands check tests that `cd` carries over, shown in the prompt line and footer
- **Manual checks:**
  - screenshots of the grid with this PC's real recent apps
  - Git Bash: `cd Pictures`, then `ls` and `cd ..`

Two checks (extensions, then quicklinks) failed once each during this work and passed on reruns. The extensions check passed three times in a row on its own. Both failures were focus and heading checks unrelated to these changes.

## Remaining limitations

- There is no Core setting to turn off the Windows usage part of the grid or to clear Core's launch list. Turning off **Settings → Privacy & security → General → Let Windows improve Start and search results by tracking app launches** stops Windows keeping the record, and the grid then shows only apps opened from Core.
- Quicklinks are not included in the recent grid.
- The working directory is shared by every shell, and shell variables do not carry over between commands.
- After `cd` into a WSL Linux folder, cmd cannot start in that folder and falls back to the Windows folder.
- There is no installer or signing.
