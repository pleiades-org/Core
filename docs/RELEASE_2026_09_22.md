# Core v2 — Windows x64 release, 22 September 2026

Portable executable: `dist/Core-v2-windows-x64/core-v2.exe`. Extract the ZIP before running. Requires 64-bit Windows and the Microsoft Visual C++ v14 x64 runtime. Core does not require administrator access. The default shortcut remains **Ctrl+Alt+Space**; existing settings files load unchanged. This is an unsigned alpha build.

## Included changes

| Area | 21 September release | This release |
| --- | --- | --- |
| App icon | Generic Windows application icon | Core artwork embedded in the executable (16–256 px) and used for the window class |
| Tray icon | Generic icon; startup failed if the tray was unavailable | Core glyph that switches white/black with the taskbar theme; added later if Explorer starts after Core and restored after an Explorer restart |
| Tray tooltip | Always "Ctrl+Alt+Space" | Shows the configured shortcut, including "Windows key" |
| Taskbar | Unreachable with an auto-hidden taskbar in Windows-key mode | `taskbar`, `tb`, `@taskbar` or `@tb` reveals and focuses the taskbar on Core's display |
| Corner rounding | Fixed 16 px | Appearance slider, 0–32 px; 0 gives square corners |
| Screen edge spacing | Always inside the work area | Appearance slider, 0–200 px from the physical screen edge; 0 keeps the automatic taskbar-aware placement; spaced windows round every corner |
| Diagnostics | Lost in release builds (no console) | Written to `%APPDATA%\Pleiades\Core\v2\core.log`, rotated to `core.log.old` above 1 MiB |
| Windows key | A key release lost on the lock screen could send the next tap to Start | State resets on session lock and unlock |
| Settings files | A byte-order mark or an unknown field disabled saving | Byte-order marks are accepted; unknown fields from newer builds are logged and ignored |
| Exit | Could wait for application discovery | Discovery is detached and cannot notify a closed window |
| Discovery | One failing packaged app stopped enumeration | Failing entries are skipped and counted in the log |
| Icons | A failed icon load stayed blank until evicted | Retried after 30 seconds |
| Saving | A temporary file left by a crash could block saving | Overwritten on the next save |

Other fixes: settings fonts are replaced before the old fonts are deleted on a DPI change; a full message queue no longer ends the message loop or shows a startup error on a second launch.

## Sliders

**Corner rounding** previews while dragging and saves on release. **Screen edge spacing** applies on release: moving the window during a horizontal drag would shift the thumb under the pointer and feed back into the value. Keyboard steps preview immediately and save after the usual 400 ms pause. Values are stored as `corner_radius` and `edge_spacing` only when they differ from the defaults, so files with default values stay readable by the 21 September build. Once a slider is changed, the 21 September build rejects the file because it does not know these fields; this and later builds ignore unknown fields instead.

Spacing is scaled for the display: 60 px at 150% scaling leaves 90 physical pixels. The native settings test verifies both slider values on a 150% display, including the physical gap, all four corners of the clipping region, saved values and the return to defaults.

## Internal changes

`launcher_state.rs` moved its settings auto-save flow into `launcher_state/settings_flow.rs`. `view.rs` moved settings forwarding, the power menu and painting into `view/`. Settings page coordinates are named constants in `settings/layout.rs` with unchanged values. Icon resources are generated from `crates/launcher/assets/source` by `scripts/generate-icons.py` and embedded by `build.rs` without a resource compiler.

## Validation

Rust: 29 engine and 30 launcher tests pass, including the ignored registry test. New tests cover the settings store (round trip, byte-order mark, stale temporary file, size limit), slider values, placement with spacing, the taskbar command, Windows-key reset, icon retry, stale-search cancellation and auto-save precedence. `cargo clippy --workspace --all-targets -D warnings` is clean.

Native scripts were run with PowerShell 7 against the packaged executable. Shortcuts were tested in registration-only mode and quicklinks without physical keyboard input, matching the previous release. The settings and integration harnesses now expect seven command hints because `@taskbar` was added.

## Remaining limitations

Taskbar reveal and the live tray glyph were not checked visually on this PC's auto-hidden taskbar. Secure-desktop, physical mixed-DPI switching, IME-candidate and screen-reader acceptance remain manual. The portable build has no installer or signing. See the [21 September notes](RELEASE_2026_09_21.md) for earlier features and limits.
