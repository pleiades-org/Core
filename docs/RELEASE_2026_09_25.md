# Core v2 — Windows x64 release, 25 September 2026

Portable executable: `dist/Core-v2-windows-x64/core-v2.exe`. Extract the ZIP before running. Existing settings, quicklinks, command history and recent apps are preserved.

## Included changes

Direct executable launches from application results and quicklinks now use the executable's folder as their working directory. Programs that load relative files such as `data/` no longer inherit Core's working directory, which may be the Windows Startup folder.

Windows retains control of shortcut (`.lnk` and `.url`), document, web-link and packaged-application launches. `@run` retains its existing working-directory behavior.

The previous time/date calculator answers, concise action hint, centred footer clock, terminal and conversion features remain included.

## Validation

- 83 engine tests and 101 launcher tests pass. Formatting and Clippy checks pass.
- An additional opt-in native regression test compiles a harmless probe and launches it through both application and quicklink actions. It failed before the fix because relative data could not be found, then passed after the fix. Paths contain spaces, non-ASCII characters and an uppercase `.EXE` extension. Three unrelated registry/network tests remain unrun.
- Packaging requires all eight background release checks to pass against this exact executable; their records are in `docs/measurements/release-*.json`.
- The installed CONTROL Resonant Steam shortcut was dispatched using the previous launch API from the Startup directory. Steam started the game, and the user confirmed it opened normally. The reported failure through that shortcut was not reproduced; the confirmed fix covers direct executable targets.
- Interactive click-away dismissal and pointer hover checks were not rerun; the package record marks them as skipped.

## Remaining limitations

The unsigned portable build requires 64-bit Windows 10 version 1809 or later and the Microsoft Visual C++ v14 x64 runtime. Physical mixed-DPI monitor switching and screen-reader acceptance remain manual checks.

An existing settings issue can leave the window at its previous position if the external foreground window used as the monitor reference has closed. Reopening Core refreshes the monitor reference. This release does not change monitor selection.
