# Core v2 — Windows x64 release, 23 September 2026 (fourth build)

Portable executable: `dist/Core-v2-windows-x64/core-v2.exe`. Extract the ZIP before running. It requires 64-bit Windows 10 version 1809 or later and the Microsoft Visual C++ v14 x64 runtime, and does not need administrator access. Settings, command history and recent apps load unchanged. This is an unsigned alpha build.

## Included changes

**Core's own terminal.** `/` commands now run in a Windows pseudo console (ConPTY), the kind of console Windows Terminal uses, and Core draws its screen in place of the result rows. Programs see a real terminal, so they behave as they do in one:
- colours, bold and underlined text, and tables;
- progress that redraws in place;
- PowerShell errors in red.

**Keys go straight to the running command.** When a command starts, the keyboard moves to Core's terminal, and each key reaches the program as it is pressed:
- answers to `set /p`, `Read-Host` and y/n questions;
- single keys, for `choice` and "press any key";
- line editing and history in REPLs such as `python`, `node` and `wsl`;
- arrows, Home/End, Page Up/Page Down, Insert/Delete, F1–F12, Tab completion and Alt combinations;
- Ctrl+C interrupts the program.

Typed keys are never saved to the command history. This replaces the previous build's line input: Enter in the search box no longer types into a running command, and Ctrl+D is now an ordinary key sent to the program.

**Full-screen programs work.** Windows 11's `edit`, and `vim`, `less`, `htop` and `ssh` through WSL, take the whole terminal.
- Esc typed in the terminal goes to the program. Esc in the search box stops it, and the footer says so.
- A full-screen program that is stopped leaves its screen, so the output returns.

**Scrolling, copying and pasting.**
- The mouse wheel, the scroll bar and Shift+Page Up/Page Down scroll back through up to 5,000 lines.
- Drag to select, then Ctrl+C, Ctrl+Insert or right-click copies. Ctrl+Shift+C always copies. Ctrl+A selects everything once the command has finished.
- Ctrl+V, Shift+Insert, or right-click with nothing selected pastes into the running command. Programs that ask are told the text was pasted, so a pasted line is not run by accident.

**Focus follows the command.**
- When a command finishes, the keyboard returns to the search box, and typing in the terminal moves there too.
- Reopening Core while a command runs puts the keyboard back in the terminal.
- Enter in finished output still does nothing, so a command is never rerun by accident.

**Directory tracking without markers.** Shells now write the folder a command finished in to a temporary file, which Core reads and deletes. Before, they wrote it into the output, which a console would show. `cd` carries over as before in Command Prompt, PowerShell, Git Bash and WSL.

**Other changes.**
- The prompt line above the output wraps instead of being cut off at the right edge.
- The 1 MB output limit is replaced by the 5,000-line scrollback, which keeps the newest output.

## Validation

- **Rust:** 83 engine tests and 98 launcher tests pass. Three ignored tests exist for the registry, live favicon and live ECB downloads; they were not rerun for this build. `cargo clippy --workspace --all-targets -D warnings` and `cargo fmt --check` are clean. New tests cover:
  - the terminal emulator:
    - delayed line wrapping and scrollback, including its 5,000-line limit;
    - cursor movement, erasing, inserting and deleting;
    - scroll regions, colours and SGR attributes;
    - the alternate screen, and status reports;
    - modes, and ignored sequences;
    - split UTF-8, and double-width characters;
  - key encoding for arrows, editing and function keys with modifiers, Backspace, Alt and bracketed paste;
  - ConPTY runs:
    - output and exit codes;
    - PowerShell errors;
    - stopping;
    - a typed answer to `set /p`;
    - a single key answering `choice`;
  - directory reports from Command Prompt, Windows PowerShell and Git Bash;
  - the prompt line wrapping, and terminal colours.
- **Release scripts:** all eight background scripts pass against the packaged executable. The first full run had one failure in the extensions script ("Confirmed power action did not reach dry-run dispatch"). That check has failed intermittently in earlier builds; it passed on two separate reruns and in a second full run of all eight. New command checks:
  - a line typed into the terminal answers `set /p` and stays out of the history;
  - a single key answers `choice`;
  - typing after a command finishes reaches the search box;
  - Esc in the terminal goes to `edit` rather than stopping it, and Esc in the search box stops it and restores the output.
- **Manual checks**, from off-screen captures of a background instance:
  - coloured PowerShell output with a table and an error;
  - the Python REPL with arrow-key line editing;
  - `edit` full-screen;
  - the view after stopping `edit`.

## Remaining limitations

- The terminal keeps the size it had when the command started. Moving Core to a display with different scaling mid-command can leave a column unused or cut one off until the next command.
- Mouse reporting to programs is not supported. Full-screen programs work with the keyboard, and the mouse wheel scrolls Core's own view.
- Combining accents that follow a letter are dropped. Precomposed characters, which consoles normally send, show correctly.
- WSL's directory report was not run live on this PC.
