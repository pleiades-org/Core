# Core v2 — Windows x64 release, 23 September 2026 (third build)

Portable executable: `dist/Core-v2-windows-x64/core-v2.exe`. Extract the ZIP before running. It requires 64-bit Windows and the Microsoft Visual C++ v14 x64 runtime, and does not need administrator access. Settings, command history and recent apps load unchanged. This is an unsigned alpha build.

## Included changes

**The Windows key opens Core reliably after it has been dismissed.** The Windows-key hook swallows the key press, so Windows did not count Core as the app that received the last input. Right after the person had used another app, Windows could refuse to bring Core to the front. Core then counted itself as open while hidden behind that app, and the next press "closed" it.
- If Windows refuses, Core now sends an empty mouse input (it moves nothing) and asks again.
- A shortcut press while Core is open but not in front brings it forward instead of hiding it.

**Windows aliases.**
- Typing a program's name finds the app whose Start Menu shortcut starts it: `cmd` finds Command Prompt, and `taskmgr`, `regedit` and `code` work the same way.
- Store apps' command names find those apps: `wt` finds Windows Terminal.
- An exact alias ranks like an exact name.
- Launcher programs that start other apps (`Update.exe`, `rundll32`, `explorer`) are not used as aliases. File Explorer is still found by its name.

**Clearer settings controls.**
- On/off settings (Start with Windows, Use Windows key) are switches, with On or Off beside them.
- Choices (Display, Commands run in) are dropdown lists with their own headings. They replace the cycling buttons.
- Actions (colour presets with a swatch, Clear command history, Done, Retry) are filled buttons, outlined in the accent colour when hovered or focused.
- The Use Windows key switch turns off back to Ctrl+Alt+Space, and typing `Win` into the shortcut field turns it on.

**Type into a running command.** While a command runs, Enter sends the prompt's text to it as a line, like typing in a terminal: answers to `set /p`, `Read-Host` or a y/n confirmation, and lines for programs reading input.
- Ctrl+D ends the input, so programs that read until the end, such as `sort`, can finish.
- Typed lines appear in the output (PowerShell prints them itself) and are never saved to the history, since they may be passwords.
- Text typed with a different shell prefix, such as `@cmd dir` while a `/` command runs, starts a new command.
- Commands used to receive empty input. A command that asks a question now waits for an answer; Esc stops it.
- This is line input, not a live terminal. Full-screen programs like `ssh` and `vim` still need Ctrl+Enter.

**Settings repaint on show.** The Screen edge spacing heading was sometimes missing from Appearance because it hadn't been repainted. It now repaints, as the power button does since the second 23 September build.

## Validation

- **Rust:** 83 engine tests and 78 launcher tests pass. Three ignored tests exist for the registry, live favicon and live ECB downloads; they were not rerun for this build. `cargo clippy --workspace --all-targets -D warnings` is clean. New tests cover:
  - alias ranking
  - shortcut targets and app execution alias records, read live from this PC
  - answering a live cmd prompt with UTF-8 text
  - ending input so `sort` finishes
- **Release scripts:** all eight background scripts pass against the packaged executable. New checks:
  - dropdowns are chosen as a person would choose them
  - the Windows-key switch turns on and off
  - a shell can be chosen from its dropdown
  - a running cmd prompt is answered from Core, and the answer stays out of the history
- **Manual checks:**
  - screenshots of `cmd`, `wt`, `taskmgr`, `code` and `explorer` searches
  - the redesigned Appearance and Behaviour pages
- **Windows-key fix:** not checked automatically. Checking it would mean bringing Core to the front while the person works. It needs confirming by pressing Win right after dismissing Core.

## Remaining limitations

- Dropdown lists use Windows' own styling, which is slightly different from Core's buttons.
- Aliases come from Start Menu shortcuts and Store app execution aliases. Programs only on PATH, or registered under App Paths without a shortcut, are not included.
