# Core v2 — Windows x64 release, 22 September 2026 (fifth build)

Portable executable: `dist/Core-v2-windows-x64/core-v2.exe`. Extract the ZIP before running. It requires 64-bit Windows and the Microsoft Visual C++ v14 x64 runtime, and does not need administrator access. Existing settings and command history load unchanged. This is an unsigned alpha build.

This build changes how the command prompt from the [fourth build](RELEASE_2026_09_22_D.md) is entered and left.

## Included changes

**A hidden `/`.** Typing `/` at the start of the search box turns it into a command prompt:
- The `/` disappears, and the empty box shows "Type a command · Backspace returns to search".
- Everything typed after that goes to the shell unchanged, including a further `/` (as in `/usr/bin/ls` under WSL).
- Pasting `/ipconfig /all` gives the prompt with `ipconfig /all` in it.

**The prompt clears after each run.**
- Enter, Ctrl+Enter and Ctrl+Shift+Enter all clear the box.
- The box stays a command prompt, so the next command needs no `/`, and the output of the last run stays visible.
- A visible shell prefix is kept, so `@cmd dir` leaves `@cmd ` in the box.
- ↑ recalls earlier commands as before.

**Backspace in the empty prompt returns to search.** It removes the hidden `/`, and the search box and result rows come back.

## Validation

- **Rust:** 78 engine tests and 61 launcher tests pass. `cargo clippy --workspace --all-targets -D warnings` is clean.
- **Release scripts:** all eight background scripts pass against the packaged executable. `test-commands.ps1` also checks:
  - a typed `/` is hidden
  - the prompt clears after a run and stays a command prompt
  - later commands run without `/`
  - Backspace in the empty prompt returns to search
  - `@cmd ` stays after a run
- **Screenshots:** the empty prompt and a finished `whoami` were checked.

The first run of the suite on this build failed three layout-size checks (extensions, styling and quicklinks). The earlier fourth build failed the same styling check in the same conditions. The cause was the active window being on another monitor: Core opens on the monitor of the foreground window, and those checks expect Core to fit at its full size there. With the active window back on the primary monitor, Core measured the expected 640 × 258 px and all eight scripts passed.

## Remaining limitations

- The layout-size release checks depend on which monitor holds the active window while they run.
- The search icon stays a magnifier in command mode. The TERMINAL label and the placeholder text show the mode.
- Ctrl+Enter and Ctrl+Shift+Enter are checked by unit tests and in dry run only. The harness cannot hold modifier keys without taking the keyboard.
- Hidden runs have no input, so interactive programs (`ssh`, `python`, prompts) end immediately. Use Ctrl+Enter for these.
- Command history is plain text. Avoid typing secrets into commands.
- There is no installer or signing.
