# Core v2 — Windows x64 release, 21 September 2026

Portable executable: `dist/Core-v2-windows-x64/core-v2.exe`. Extract the ZIP before running. Requires 64-bit Windows and the Microsoft Visual C++ v14 x64 runtime, which is already available on this PC. Core itself does not require administrator access. The default shortcut remains **Ctrl+Alt+Space**; existing appearance settings are preserved. This is an unsigned alpha build.

## Included changes

The latest update adds saved Quicklinks and expands Settings with Appearance, Behaviour and Quicklinks in a left sidebar and the selected category's controls on the right. Valid edits save automatically, with a 400 ms typing delay for color and shortcut fields and immediate saves for buttons. Saving, saved and error states are visible; failed writes offer Retry save. Done returns to search after saving. Existing preferences are retained.

The panel fits its entire contents to the monitor work area at large display scales. Position previews, pure-black styling, rounded controls and existing hover effects remain available. The controls and cached fonts are created only when Settings is first opened.

The footer and power popup now use the actual client dimensions after Windows limits the window to the monitor work area. This fixes a reproduced case where the default eight application rows put the power button below the screen at large display scales. The result viewport shrinks without discarding results; keyboard navigation scrolls to the remaining entries. Earlier tests opened the power menu after a single calculator result and did not check control containment, so they missed this case. The new native controls test starts with an untouched empty query, exercises constrained sizing, and checks visibility after settings and reopening.

## Quicklinks

Settings has a Quicklinks category with Link and Name columns. A completed row adds a trailing blank row; scrolling reuses four rows of native controls regardless of saved count. Rename either field or remove a row with its × button. Up to 1,000 entries are supported. Names are unique ignoring case, with a 120 UTF-16-unit limit; targets are limited to 2,048 UTF-8 bytes. Incomplete/invalid edits show a row-specific explanation and are never written. Other completed changes remain subject to the shared all-valid-fields autosave rule.

HTTP/HTTPS links open in the browser; bare domains are normalized to HTTPS. Absolute drive paths and ordinary UNC file/folder paths open through Windows. Executable command strings, custom URI schemes and device paths are not accepted. Search never checks the filesystem or fetches a URL; a missing target is reported only on activation.

Quicklinks participate in normal app/name ranking and can be searched separately with `>` or `@quicklink`. `@app` remains app-only. Catalogs are prepared on the search worker only when applications or saved quicklinks change, with snapshots shared across requests. No extra idle worker, timer, network request or dependency is added. Editing a table cell does not recreate appearance brushes or reposition the entire window.

Quicklinks and preferences are atomically saved together in `appearance.ini`. Version-1 files still load; nonempty quicklinks use version 2 so older builds preserve rather than overwrite unsupported data. The settings reader is bounded to 4 MiB. Restart, rename, deletion, duplicate/unsupported-target rejection, 31-row growth, GDI-handle stability, shared/scoped search, dry-run activation and denied-write recovery pass native tests. Header pixels are checked in captures after repeated edits. Physical Tab testing remains manual for this candidate because the shared desktop received unrelated input. Table data tests use `--dry-run --test-stay-open` to isolate focus changes; normal click-away behavior is checked separately.

## Calculator examples and semantics

| Input | Result / meaning |
| --- | --- |
| `2 days from now`, `in 2 weeks`, `3 days ago` | A calendar date relative to the local date when searched |
| `today`, `tomorrow`, `yesterday` | Local calendar date |
| `next Friday`, `last Mon` | Strictly next/previous weekday; the same weekday means seven days away |
| `3 hours ago`, `in 10 minutes`, `now` | Local time and date; elapsed minutes/hours are added in UTC before local DST conversion |
| `2028-01-31 + 1 month` | 29 February 2028; month/year changes clamp to the last valid day |
| `1 year after 2028-02-29` | 28 February 2029 |
| `2 days before 2026-01-01` | 30 December 2025 |
| `2026-12-25 - 2026-09-21` | 95 days; signed difference, end minus start |
| `10 kg to lb`, `100cm to m`, `2 days in hours` | Numeric unit conversion |
| `32 f to c`, `100c to f`, `0 k to c` | Celsius, Fahrenheit and kelvin; below absolute zero is rejected |
| `sqrt(81) + round(2.6)` | 12 |
| `abs(-7)`, `floor(2.9)`, `ceil(1.1)`, `cbrt(27)` | Real-number functions |
| `ln(e)`, `log(100)`, `log10(1000)`, `log2(8)` | Natural/base-10/base-2 logarithms |
| `sin(pi/2)`, `cos(0)`, `tan(0)`, `tau/2` | Trigonometry in radians; pi, e and tau constants |

These also work after `@calc`. Existing time-zone commands remain available. Dates are limited to 1900–2100; date offsets are whole numbers. Days/weeks/months/years are calendar operations. Hour/minute phrases measure elapsed time. Arithmetic uses IEEE-754 floating point, not arbitrary precision; formatting retains the numerical result and uses compact scientific notation for extremes. Percent remains division by 100. Function domain errors do not return copy actions.

Units cover mm/cm/m/km/in/ft/yd/mi, mg/g/kg/lb/oz, seconds/minutes/hours/days/weeks, ml/litres, and C/F/K. Months and years are not fixed-duration conversion units. Currencies, arbitrary natural language, business-day calendars and composite quantities such as `5 ft 10 in` are outside this build.

Enter copies the number for arithmetic/conversions/day differences, an ISO date for calendar answers, and `YYYY-MM-DD HH:MM` for local elapsed-time answers. Time-zone results retain their dated destination-zone text. Results are evaluated on query/open, with no idle clock polling.

## Settings and power

Appearance changes preview immediately. All valid settings save automatically; controls remain usable while a write is pending, with only the latest queued edit retained. Color and shortcut text wait 400 ms after typing. Button choices save immediately. Done, Escape, clicking away and normal exit flush valid pending edits. Invalid fields show an explanation and retain the last saved preferences on dismissal. A failed write preserves the previous file and shows Retry save; shortcut/startup changes roll back if saving fails. Forced termination during the typing delay is not a normal exit and cannot flush that edit.

Shortcut examples: `Ctrl+Alt+Space`, `Alt+Shift+K`, `Win+Shift+7`, `F12`, or `Win` alone. The **Use Windows key** button enters the last option. Either Windows key toggles Core on release; a bare tap is suppressed before reaching Start. Modifier combinations use a brief key replay on a dedicated message-loop thread. Windows can restrict replay into elevated applications; use a regular shortcut in that case. Exiting Core restores ordinary Windows-key behavior.

**Display** cycles through Active and connected Windows display identifiers. Active means the foreground application's monitor when opening Core. The chosen display identifier is retained if unplugged, and placement falls back to Active. Work areas exclude the taskbar. Settings uses a left sidebar with Appearance, Behaviour and Quicklinks categories, adapting its scale to keep every control visible.

**Start with Windows** stores a quoted path with `--start-hidden` in the current user's `Software\Microsoft\Windows\CurrentVersion\Run`, value `PleiadesCoreV2`. It runs at user sign-in, not before login. Keep the executable in a permanent folder before enabling it. No scheduled task/service or administrator permission is involved. A failed settings-file save restores the previous startup registry value. External disablement through Windows Startup Apps is not monitored continuously.

Power options are available as `@power`, `@power shutdown`, `@power restart`, `@power sleep`, or the exact plain queries `power off`, `shutdown`, `restart`, `sleep`. The icon menu offers Sleep, Restart and Power off. Arrow keys move between icons; Escape closes the menu first. Choosing an action opens Cancel and Confirm rows with Cancel selected. Power off/restart do not force applications closed. Sleep requests the system's normal sleep behavior; supported states remain subject to the hardware and Windows settings.

Preferences stay in `%APPDATA%\Pleiades\Core\v2\appearance.ini`. Existing version-1 appearance files load with defaults for the new optional fields. The file remains bounded, versioned and atomically replaced by a short-lived save worker.

## Efficiency and validation

The engine adds no dependencies. Parsing remains bounded; arithmetic borrows the query and uses a bounded Pratt parser, date tokenization uses a small stack buffer, and date offsets use bounded calendar operations instead of looping over the requested number of days. Normal shortcuts use RegisterHotKey; only Windows-key-only mode adds a sleeping hook thread. AppsFolder enumeration runs once on the discovery worker. Icons still load only for visible results, through the bounded cache. The recessed menu uses native drawing without a blur buffer or animation timer.

44 Rust tests pass, including an explicit isolated-registry startup/rollback integration test and constrained-layout regressions. Strict Clippy and formatting pass. Native checks cover all seven anchors/corner masks, calculator routing, stale Enter actions, time-zone DST gaps/overlaps, power cancellation/confirmation in dry-run mode, Xbox discovery, icons, menu keyboard behavior, shortcut registration/conflict recovery and graphics-handle stability. Physical Windows-key taps and modifier combinations passed on the preceding build; injection was not repeated on this candidate while the desktop was in use. Settings checks cover automatic saves while the panel stays open, all five preferences restored after restarting, denied replacement and Retry recovery, rapid edits, invalid text, dismissal/reopen during a pending save, exit during the typing delay, sidebar placement and constrained DPI. Controls checks also verify pointer entry/exit rendering on all four power icons, hover cleanup when the menu closes, and no GDI-handle growth during repeated hover. Hover uses native events with no polling or animation timer; screen previews use the existing drawing helpers and add no dependencies.

Power execution itself is intentionally not exercised on the user's PC. Actual boot/login startup, secure desktop/elevated shortcut replay, screen-reader behavior and physical mixed-DPI monitor changes remain manual acceptance checks. Native tests use isolated settings files and identify the exact executable hash in their JSON records.

The shortcut harness now waits for startup registration before injecting input. The desktop-click harness waits for cursor positioning before clicking; the earlier build also exhibited failures without that synchronization. A pre-existing shutdown diagnostic remains: shortcut unregistration can report an invalid window handle after window destruction; Windows releases that binding when the launcher thread exits.
