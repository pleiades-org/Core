# Core v2 — Windows x64 release, 22 September 2026 (third build)

Portable executable: `dist/Core-v2-windows-x64/core-v2.exe`. Extract the ZIP before running. It requires 64-bit Windows and the Microsoft Visual C++ v14 x64 runtime, and does not need administrator access. Existing settings load unchanged. This is an unsigned alpha build.

## Included changes

**Commands from the search box.** Type `/` followed by a command. Everything after the `/` goes to your shell unchanged. The [command reference](COMMANDS.md) has the details.

| Input | What happens |
| --- | --- |
| `/ipconfig /all` | Runs hidden. Output streams into a panel below the results, and the footer shows the shell, exit code and duration. |
| `/` | Lists recent commands. Enter puts one back in the box. |
| `@cmd`, `@ps`, `@pwsh`, `@wsl`, `@bash` | Run a command in a specific shell. |
| `@run notepad`, `shell:startup`, `ms-settings:display`, `%temp%`, `\\nas\share` | Open the target as Windows Run (Win+R) would. A **Run as administrator** row is included. |

- Each command also offers **Open in terminal** (Windows Terminal if installed, otherwise a console window) and **Run as administrator**.
- **Esc** stops a running command and everything it started. The next Esc hides Core.
- **Tab** moves into the output panel. There, Ctrl+A and Ctrl+C select and copy, and Enter never reruns the command.
- History is saved newest first in `command-history.txt`, next to your settings. At most 100 commands are kept.
- **Settings → Behaviour** has two new controls:
  - **Commands run in** defaults to Windows Terminal's default profile. If Core can't use that profile, it falls back to Windows PowerShell.
  - **Clear command history** deletes the saved history.

**Website icons from Google's favicon service.** Website quicklinks now request `https://www.google.com/s2/favicons?domain=<site>&sz=64`, which finds icons declared only in page HTML. If that fails, Core falls back to the site's own `/favicon.ico`. Private hosts are never sent to Google: `localhost`, bare machine names, `.local`, `.lan`, `.internal`, `.home.arpa` and `.localhost` names, and IP addresses. Icons are cached for 30 days in a new cache format, so every website quicklink downloads its icon once again after upgrading. An icon now appears as soon as it downloads. Previously, a newer icon batch could discard icons that had already been fetched.

**Tests no longer take your focus.** Release scripts run by default in a background mode (`--test-background`), in which Core never takes the foreground, moves the pointer or types. Checks that need the real foreground and pointer (click-away dismissal and pointer hover) run only with `scripts\run-release-checks.ps1 -Interactive`.

## Network use

Searching never uses the network. Typing a `/` command sends nothing either, though a command you run can use the network itself. Background network features are unchanged except for the icon source above:

- **Website icons** are requested from Google, then from the site itself.
- **Exchange rates** are downloaded from the European Central Bank.

Neither runs in `--dry-run` unless `--test-network` is given.

## Validation

- **Rust:** 78 engine tests and 59 launcher tests pass, including ignored tests run explicitly for the registry, live favicon and live ECB downloads. `cargo clippy --workspace --all-targets -D warnings` is clean. New tests cover:
  - `/` and `@` parsing, and Run-target detection
  - shell resolution from Windows Terminal settings, including unquoted paths with spaces
  - argument quoting and the UTF-8 command wrappers
  - output decoding: split UTF-8, ANSI stripping, OEM fallback
  - history ordering and limits
  - live capture, exit codes and stop
- **Release scripts:** all eight background scripts pass against the packaged executable. The new `test-commands.ps1` runs `/echo` in the default shell and checks:
  - `@cmd exit /b 3` reports exit code 3
  - Esc stops a streaming `ping` and keeps Core open
  - history appears under `/` and is saved newest first
  - the panel hides outside `/` mode
  - `@run` and bare `ms-settings:` rows appear, and dry run opens nothing
- **Focus:** a foreground monitor sampling every 25 ms during the full background run recorded no Core or harness window in the foreground.
- **Manual check:** `/whoami`, stopping `ping` with Esc, and the history list were checked in the running app.

## Remaining limitations

- Hidden `/` runs have no input, so interactive programs (`ssh`, `python`, prompts) end immediately. Use **Open in terminal** for these.
- Command history is plain text. Avoid typing secrets into commands.
- **Run as administrator** and **Open in terminal** were checked only in dry run. Neither was launched by the automated tests.
- Dark favicons can be hard to see on black.
- Secure-desktop, physical mixed-DPI switching, IME-candidate and screen-reader acceptance remain manual.
- There is no installer or signing.
